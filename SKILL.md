# OB Swift Figma

Build GeneralOB onboarding pages from Figma by first confirming the current project contains the required `GeneralOB` architecture, then learning the project and implementing inside that architecture. New Figma pages must live in `GeneralOB/Pages`; ordinary pages inherit from `GeneralOBVC`, option-style pages inherit from `GeneralOBCollectionVC`, and every page maps one-to-one with `GeneralOBPage`. Fidelity matters, but local fit wins over isolated generated code.

## Workflow

1. Before reading Figma or starting any page task, locate the engineering project root and verify it contains an `OB-Task-Doc` folder. If the folder is missing, copy the skill-bundled `assets/OB-Task-Doc` folder into the project root as `OB-Task-Doc`; keep it as a root documentation folder only, and do not add it to the Xcode project file, app target, build phases, or Copy Bundle Resources.
2. Before reading Figma or starting any page task, verify the project contains a complete `GeneralOB` folder with `GeneralOBCollectionVC.swift`, `GeneralOBPage.swift`, `GeneralOBPage+Data.swift`, `GeneralOBPage+VC.swift`, `GeneralOBVC.swift`, `DataModel/`, and `Pages/`. If the folder is missing or incomplete, copy the skill-bundled `assets/GeneralOB` folder into the app source directory that is one level below the `.xcodeproj`-level directory, not beside the `.xcodeproj` at that top level; add the copied Swift files to the primary app target, re-run the same filesystem and target-membership verification, and do not continue by creating stub replacement files.
3. At task start, automatically read `OB-Task-Doc/OBFigma.md` when it exists, falling back to legacy `GeneralOB/OBFigma.md` when needed; parse page blocks such as `## 001`, their names, all Figma URLs inside the block, any `### announcement` content, and any existing `ob-status` marker.
4. Pick the first page that is not marked `done`; if a page is marked `failed` or `in_progress`, retry that same page before moving to later pages.
5. Mark the selected page as `in_progress` in `OBFigma.md` before implementation with a lightweight status marker such as `<!-- ob-status: in_progress; attempts: 1 -->`.
6. Read every Figma URL in the selected page block with the available Figma tools. Treat multiple Figma links in one block as multiple UI states of the same page, not separate page tasks.
7. If the selected block has `### announcement`, treat every statement under it as a hard page-level implementation condition, satisfy it before marking the page `done`, and let it override generic page-shape heuristics when they conflict. If the announcement mentions a reference image, reference document, attachment, filename, or relative path, search `OB-Task-Doc/` first and use that file as the authoritative reference before checking any other project location.
8. Inspect the iOS project before editing: `GeneralOB/Pages`, `GeneralOBPage`, `GeneralOBPage+Data.swift`, `GeneralOBPageData`, base classes, page routing, existing components, design tokens, assets, pods, and nearby screens.
9. Plan the mapping from Figma layers to current project primitives, naming every reused component, base class, helper, asset, and library, plus how each announcement condition will be satisfied.
10. Add or update exactly one `GeneralOBPage` case for each new Figma page, then map that case to exactly one page implementation.
11. Name each new page file and class as `OB<Page>VC`, where `<Page>` is the PascalCase form of the `GeneralOBPage` case, such as `OBStartVC.swift` / `OBStartVC`.
12. Implement each ordinary Figma page in `GeneralOB/Pages` as a `GeneralOBVC` subclass or by extending the existing `GeneralOBVC` page flow, using the project's existing UI style, layout system, scaling helpers, font APIs, colors, lifecycle, and state patterns.
13. For option-style pages, subclass `GeneralOBCollectionVC`, source the option model from `GeneralOBPage.pageData.items`, and override only the necessary hooks such as `registerCell` and `cell(_ c: UICollectionView, path: IndexPath)` instead of rebuilding collection view plumbing from scratch, unless the page announcement explicitly forbids `UICollectionView`.
14. For option-list pages, set `page.multipleSelected = true` when the Figma interaction supports multiple selections; otherwise leave or set it to `false`.
15. For option-list pages, set `page.cellHeightIsConsistent = true` when every list cell has the same height in the Figma design; set `page.cellHeightIsConsistent = false` when cell heights can differ because of layout, expanded state, multiline content, or per-option design differences.
16. For list pages or any non-list page with tap-to-select behavior, add a matching property to `GeneralOBData` for persisted selection state: single-select index state uses `var page: Int?`, and multi-select index state uses `var page: [Int]?`, where `page` is the project-consistent property name for that `GeneralOBPage`.
17. For list pages, restore and save selection with `vc.makeSelectIndexes(...)` only in the external `GeneralOBPage` `page.vc` creation path; keep `makeSelectIndexes` out of `OB<Page>VC`, cells, and page-local helpers. Unless Figma or the page announcement explicitly specifies an initial selected option, do not provide a default selected index in `page.vc`; use only `GeneralOBData` for restored selection, and when `GeneralOBData` has no saved value call `vc.makeSelectIndexes([])`.
18. For non-list pages with tap-to-select behavior, restore selection from `GeneralOBData` during page setup, update the selected UI in the page's own state-rendering code, and save changes back to `GeneralOBData` in the tap handler; do not use `makeSelectIndexes` for non-list selection.
19. Initialize option items with both raw and localized titles, for example `GeneralOBPageItem(title: "abc", localizedTitle: #Localized("abc"), icon: "...")`.
20. When Figma shows an icon in a list item, export and use that exact Figma image asset for the item's `icon`, including its selected or unselected state where applicable. Do not substitute a Figma list icon with an SF Symbol, `UIImage(systemName:)`, `systemName:`, a drawn shape, or a runtime vector.
21. Never call `UICollectionView` reload methods such as `reloadData()`, `reloadItems(at:)`, or `reloadSections(_:)`; rely on `GeneralOBCollectionVC` data flow, diffable snapshots, selection APIs, or targeted state updates instead.
22. Do not call `makeSelectItems`, `makeSelectIndexes`, or any `makeSelect*` method inside the page implementation; those methods are reserved for the external code path that creates and initializes list page VCs.
23. For bottom continue button enabled, disabled, color, title color, or other state differences, override the inherited `nextBtnEnable` property and implement the state changes in its `didSet`; do not create a new helper method such as `updateNextButtonState`.
24. When using `UIImageView` in page code, create it without assigning `contentMode`; do not set `.scaleAspectFit`, `.scaleAspectFill`, `.center`, or any other `contentMode` in the page implementation.
25. When subclassing `GeneralOBBaseCell`, add new controls to `baseView`, prefer the inherited `titleLab`, `icon`, `checkIcon`, and `selectedBaseView`, implement `checkIcon` selected and unselected states with image assets only, call `super.setupUI()` in overridden `setupUI`, and use SnapKit `snp.remakeConstraints` when adjusting inherited constraints.
26. If a list cell's selected UI differs from the base class behavior, override `isSelected` in the cell subclass and apply the correction in `didSet`, using inherited controls such as `selectedBaseView`, `checkIcon`, `titleLab`, and `icon` where possible.
27. Localize every user-visible string with `#Localized("...")` and add `import OOGMacroKits` at the top of Swift files that use the macro.
28. When a page contains privacy policy and terms-of-use agreement text, implement it with `GeneralLinkTextView.createLinkView`, localized `Privacy Policy`, localized `Terms of Use`, localized `By continuing you agree to the %@ and %@`, and clickable `QACheck.PRIVACY_URL` / `QACheck.TERM_OF_USE_URL` links; do not use a plain `UILabel` or non-clickable attributed text for this agreement copy.
29. Add or update assets only when they are present in Figma or explicitly required; export Figma images as PNG resources with `2x` and `3x` variants, not SVG; put each page's exported image assets inside the matching `GeneralOBPage` folder under the `GeneralOB` asset namespace.
30. Keep title and subtitle layers above all other page content, including images, collection views, cards, decorations, gradients, and background art.
31. When the Figma page frame height is greater than `844`, put page content into a scrollable area while keeping the bottom continue button outside that scroll view so it stays fixed and visually floats above scrolling content.
32. Map Figma chrome visibility to `GeneralOBPage` metadata: no top-left back button means `page.canBack = false`, no top progress bar means `page.isHideProgress = true`, and no bottom continue button means `page.isHideContinueBtn = true`.
33. Verify compile-time integration, layout responsiveness, safe areas, iPad or small-device variants, visual fidelity against the Figma screenshot, scroll behavior for frames taller than `844`, persisted selection restore/save behavior for both list and non-list selectable pages, Figma list-item icon asset use with no system-symbol fallback, cell subclass `isSelected.didSet` corrections when required, clickable privacy/terms agreement links when present, and all announcement conditions.
34. On success, mark the page `done` in `OBFigma.md`, stage only the current page's implementation, asset, project, and status-marker changes, create one git commit for that page, then continue to the next not-done page.
35. On failure, mark the page `failed` in `OBFigma.md` with the attempt count and short reason, do not continue to later pages, and retry the current page from its status marker on the next run.
36. Summarize changed files, reused project primitives, page status updates, commit hashes, announcement conditions and how they were satisfied, any fidelity compromises, and verification results.

## Project Fit Rules

- When `OB-Task-Doc/OBFigma.md` exists, treat it as the primary page queue for this skill. Use legacy `GeneralOB/OBFigma.md` only when `OB-Task-Doc/OBFigma.md` is absent. Parse page blocks in document order, preserve user-authored text and Figma links, and edit only the status marker lines needed for execution state.
- Before queue parsing, Figma reading, or Swift editing, confirm the project root has `OB-Task-Doc`. If not, copy the skill-bundled `assets/OB-Task-Doc` folder into the engineering project root; do not add `OB-Task-Doc` to `.xcodeproj`, project groups, app targets, build phases, or Copy Bundle Resources.
- Before queue parsing, Figma reading, or Swift editing, confirm the project has a complete `GeneralOB` folder with the required base files and folders. If not, identify the app source directory that sits one level below the directory containing `.xcodeproj` and copy the skill-bundled `assets/GeneralOB` folder there as `GeneralOB`; do not place it beside the `.xcodeproj` in the top-level project directory. Add every copied Swift file to the primary app target's Compile Sources, and verify both the required structure and target membership before continuing.
- A single `OBFigma.md` page block may contain multiple Figma links. All links in the same block belong to the same `GeneralOBPage` case and `OB<Page>VC` implementation, and represent different UI display states such as selected, disabled, expanded, empty, error, or alternate content states. Do not split them into separate pages, enum cases, files, or commits.
- A page block may contain a `### announcement` section. Treat all text under that heading until the next heading of the same or higher level as hard page-level implementation constraints for that page. Satisfy every announcement condition before marking the page `done`, and report how each condition was met.
- If a page announcement mentions a reference image, reference document, attachment, filename, or relative path, resolve it from `OB-Task-Doc/` first. Use `rg --files OB-Task-Doc` or direct path checks before searching elsewhere, and report the resolved reference path.
- If a page announcement conflicts with generic inference from Figma or with a reusable default in this skill, the announcement wins for that page unless it violates non-negotiable project boundaries such as UIKit GeneralOB integration, localization, or asset safety. Call out any such conflict instead of silently choosing the generic rule.
- For example, an announcement of `不使用UICollectionView` means the page must not use `UICollectionView`, `GeneralOBCollectionVC`, collection cells, or collection reload/update APIs, even if the Figma layout looks like a selectable option list. Implement it as an ordinary `GeneralOBVC` page or another existing non-collection project pattern while still preserving `GeneralOBPage` mapping and page data rules that remain applicable.
- Use a lightweight page status marker inside each `OBFigma.md` page block, for example `<!-- ob-status: todo -->`, `<!-- ob-status: in_progress; attempts: 1 -->`, `<!-- ob-status: failed; attempts: 1; reason: build failed -->`, or `<!-- ob-status: done; commit: <hash> -->`. Missing status means `todo`.
- Complete and commit one `OBFigma.md` page block at a time. After a page passes verification, update its status to `done`, run `git status` and `git diff`, stage only files belonging to that page plus the `OBFigma.md` marker, commit with a page-specific message such as `Implement OB 001 body reading begins`, then proceed to the next page.
- If the current page fails, update only that page's marker to `failed` with an attempt count and short reason, keep enough context for automatic retry, and retry that same page before processing any later page. Do not mark later pages or skip ahead while a failed page remains.
- Prefer existing local components, `GeneralOBVC`, `GeneralOBCollectionVC`, extensions, and pods over new abstractions.
- Do not implement these Figma pages as standalone `UIViewController`, direct `OBBaseViewController` subclasses, or SwiftUI screens unless the user explicitly changes this skill's boundary.
- Place all new Figma page implementation files under `GeneralOB/Pages`; place reusable page data models under `GeneralOB/Pages/Model` only when the existing `GeneralOBPageData` shape is insufficient.
- New page file names and class names must use `OB<Page>VC`, where `<Page>` follows the `GeneralOBPage` case in PascalCase; for example `.start` maps to `OBStartVC.swift` and `OBStartVC`.
- Every user-visible string must be wrapped with `#Localized("...")`, including labels, button titles, option titles, tag titles, cell text, subtitles, descriptions, and `GeneralOBPage.pageData` text; any Swift file using that macro must include `import OOGMacroKits` near the top.
- If a page includes the agreement sentence with `Privacy Policy` and `Terms of Use`, implement it as a clickable `GeneralLinkTextView` using the project agreement snippet in `references/implementation-workflow.md`; the privacy and terms substrings must link to `QACheck.PRIVACY_URL` and `QACheck.TERM_OF_USE_URL`.
- For this project family, every new Figma onboarding page should inherit from `GeneralOBVC` and continue to use `GeneralOBPage`, `GeneralOBPage.pageData`, `OBPage`, `OnboardingPagesDataSource`, `Components`, `SnapKit`, and `OOGFontKit` patterns.
- Keep `GeneralOBPage` and page implementations one-to-one: one enum case owns one page class or one clearly isolated `GeneralOBVC` rendering branch.
- Match Figma navigation chrome with `GeneralOBPage` flags: if the design has no top-left back button, set that page's `canBack` to `false`; if it has no top progress bar, set `isHideProgress` to `true`; if it has no bottom continue button, set `isHideContinueBtn` to `true`.
- For option-style Figma pages, inherit from `GeneralOBCollectionVC`; define option data in `GeneralOBPage.pageData` with `GeneralOBPageData` and `GeneralOBPageItem`; override `registerCell` and `cell(_ c: UICollectionView, path: IndexPath)` for the page-specific cell; do not create a fresh collection view data source, delegate stack, or selection pipeline.
- If the current page announcement forbids `UICollectionView`, do not apply the option-style `GeneralOBCollectionVC` rule for that page. Use a non-collection implementation and explicitly verify that no `UICollectionView` symbols were introduced in the page-specific files.
- For option-list Figma pages, set `page.multipleSelected = true` when the page supports multi-select; otherwise ensure it remains `false`.
- For option-list Figma pages, set `page.cellHeightIsConsistent = true` when all collection cells have the same rendered height; set `page.cellHeightIsConsistent = false` when Figma shows variable heights or any selection/content state can change cell height.
- When Figma includes an icon in a list item, each matching `GeneralOBPageItem.icon` must reference the Figma-exported PNG asset in the page namespace. Do not replace those icons with SF Symbols, `UIImage(systemName:)`, `systemName:`, generated vector drawing, or generic system artwork; export distinct selected and unselected Figma icon assets whenever the design shows distinct states.
- For list pages or any non-list page with tap-to-select behavior, add a matching persisted selection property to `GeneralOBData`. Use `var page: Int?` for single-select index state and `var page: [Int]?` for multi-select index state, where `page` is replaced with the project-approved property name for the `GeneralOBPage` case.
- For list pages, in the external `page.vc` creation path for the matching `GeneralOBPage`, restore and save selected index paths with `vc.makeSelectIndexes`. Single-select restores `[IndexPath(item: data, section: 0)]` from `GeneralOBData.shared.page` and saves `arr.first?.item`; multi-select restores `data.map { IndexPath(item: $0, section: 0) }` and saves the selected indexes array. If there is no saved value in `GeneralOBData`, call `vc.makeSelectIndexes([])`; do not default to selecting the first option or any other option unless Figma or an announcement explicitly requires that initial state.
- List-page selection restore/save belongs in the external `GeneralOBPage` `page.vc` or equivalent VC construction location. Do not put `makeSelectIndexes`, `makeSelectItems`, or any `makeSelect*` call inside `OB<Page>VC`, custom cells, or page-local selection/layout code.
- For non-list pages with tap-to-select behavior, do not use `makeSelectIndexes`. Restore the current value from `GeneralOBData` when building the page UI, render the selected/unselected state through a page-local state method or property, and update `GeneralOBData` whenever the user taps to change selection.
- Do not call `UICollectionView` reload APIs anywhere in Figma page implementations, including `reloadData()`, `reloadItems(at:)`, `reloadSections(_:)`, or wrapper helpers that call them. Use the existing `GeneralOBCollectionVC` diffable data source, `mainPage.pageData.items`, selection methods, and direct cell state updates instead.
- Do not call `makeSelectItems`, `makeSelectIndexes`, or any `makeSelect*` method from inside `OB<Page>VC`, cells, or page-local layout/selection code. For list pages, initial selection setup through `makeSelect*` belongs only to the external page creation or VC initialization location; for non-list tap-to-select pages, restore and save selection directly through `GeneralOBData`.
- Customize bottom continue button states by overriding `nextBtnEnable` and putting all enabled/disabled UI changes in its `didSet`, following `GeneralOBVC` and nearby pages such as `OBSexVC`. Do not add a new method or helper solely to refresh bottom button state.
- Do not assign `contentMode` on `UIImageView` instances in page implementations, page-local custom views, or cells; create image views and set their image/constraints without `.contentMode = ...`.
- Initialize every option `GeneralOBPageItem` with a raw `title` and localized `localizedTitle`, using the form `GeneralOBPageItem(title: "abc", localizedTitle: #Localized("abc"), icon: "...")`; do not set only `localizedTitle`, and do not place option display strings directly in cells.
- When creating a custom cell by subclassing `GeneralOBBaseCell`, add any new labels, image views, buttons, or containers to `baseView`; prefer reusing inherited `titleLab`, `icon`, `checkIcon`, and `selectedBaseView` before adding replacements; implement `checkIcon` selected and unselected states with cut image resources such as `image` and `highlightedImage`, never with pure colors, borders, drawn shapes, SF Symbols, or runtime vector drawing; if the inherited layout does not match Figma, update those controls with `snp.remakeConstraints`; any overridden `setupUI` must call `super.setupUI()`.
- If the current list page's selected cell UI does not match the base class selected-state behavior, override `isSelected` in the custom cell subclass and apply the UI correction in `didSet`. Keep the correction cell-local and use inherited controls such as `selectedBaseView`, `checkIcon`, `titleLab`, and `icon`; do not move selected UI correction into the page VC or external selection persistence code.
- If an option-list cell's selected background style is not a pure color, such as a gradient, image, textured fill, multi-layer shape, or other complex Figma background, implement that selected background through the inherited `GeneralOBBaseCell.selectedBaseView`. Do not add a separate method such as `updateSelectedBackground`, `refreshSelectedStyle`, or a page-specific selected-background toggle method just to handle that state.
- When Figma reports a component corner radius of `99` or `999`, treat it as a capsule shape and set the Swift corner radius to half of the component height, such as `height / 2` or `cx390(height) / 2`, instead of copying `99` or `999`.
- Exported Figma images for a page must use PNG format with `2x` and `3x` variants; do not export or commit SVG for these page assets. Store them with the `GeneralOB/<page>/...` asset namespace pattern under `GeneralOB/Assets.xcassets/GeneralOB/<page>/`, where `<page>` matches the `GeneralOBPage` case or project-approved page asset name; enable `provides-namespace` for both `GeneralOB` and `<page>` folders; reference images with namespaced asset names such as `UIImage(named: "GeneralOB/<page>/<assetName>")`.
- Title and subtitle views must have a higher visual layer than all other content. Add them after background/content views or call `view.bringSubviewToFront(...)` / set an appropriate `layer.zPosition` so they cannot be covered by images, collection cells, decorative overlays, or gradients.
- If the Figma page frame height is greater than `844`, the page's main content must scroll. Use the project's existing scroll pattern, such as `UIScrollView` plus a content view or the inherited collection view when allowed, and constrain the scrollable content below the top chrome/title area and above the bottom button area.
- For pages taller than `844`, keep the bottom continue button outside the scrollable content and attached to the existing `GeneralOBVC` bottom button layer or a fixed bottom overlay. The button must not move with content scrolling, and it should visually float above the scroll view with enough bottom inset/content inset so the last content is not hidden under the button.
- Use `rg` to locate helpers such as `cx390`, `UIColor("#...")`, `cornerRadius`, typography extensions, asset names, routers, and existing reusable controls before writing substitutes.
- Do not overwrite user code, remove unrelated files, or change project architecture just to match a Figma frame.
