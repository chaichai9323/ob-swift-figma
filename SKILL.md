# OB Swift Figma

Build GeneralOB onboarding pages and shared onboarding foundations from Figma by first confirming the current project contains the required `GeneralOB` architecture, then learning the project and implementing inside that architecture. A section whose normalized heading is `BaseCell`, including `# BaseCell` or `## BaseCell`, is a shared-foundation specification for `GeneralOBBaseCell`, the shared back icon, and `GeneralOBVC.nextButton`, not an OB page; actual pages live in `GeneralOB/Pages`, follow the required base-class branch, and map one-to-one with `GeneralOBPage`. Fidelity matters, but local fit wins over isolated generated code.

## Workflow

1. Before reading Figma or starting any page task, locate the engineering project root and verify it contains an `OB-Task-Doc` folder. If the folder is missing, copy the skill-bundled `assets/OB-Task-Doc` folder into the project root as `OB-Task-Doc`; keep it as a root documentation folder only, and do not add it to the Xcode project file, app target, build phases, or Copy Bundle Resources.
2. Before reading Figma or starting any page task, verify the project contains a complete `GeneralOB` folder with `GeneralOBCollectionVC.swift`, `GeneralOBPage.swift`, `GeneralOBPage+Data.swift`, `GeneralOBPage+VC.swift`, `GeneralOBVC.swift`, `DataModel/`, and `Pages/`. If the folder is missing or incomplete, copy the skill-bundled `assets/GeneralOB` folder into the app source directory that is one level below the `.xcodeproj`-level directory, not beside the `.xcodeproj` at that top level; add the copied Swift files to the primary app target, re-run the same filesystem and target-membership verification, and do not continue by creating stub replacement files.
3. At task start, automatically read `OB-Task-Doc/OBFigma.md` when it exists, falling back to legacy `GeneralOB/OBFigma.md` when needed. Parse an optional section whose normalized heading is `BaseCell`, including `# BaseCell` or `## BaseCell`, separately from every page block such as `## 001`. The BaseCell section ends before the first subsequent `## <id>` page block or the next heading of the same or higher level, whichever comes first. Every BaseCell Figma link must visibly include its cell state, back button and bottom next button; if either shared button is absent, stop and report missing design evidence instead of inferring its style from a page. The parent processes this shared section before page dispatch. It may change only the existing `GeneralOBBaseCell` declaration, the shared `GeneralOBVC.nextButton` UI declaration, and the shared `GeneralOB` asset namespace limited to its parent `Contents.json` plus `icon_back.imageset`. Implement the cell's unselected treatment through `baseView` and selected container effect through `selectedBaseView`. Export the Figma back button as a 44x44 pt shared PNG image set at `Assets.xcassets/GeneralOB/icon_back.imageset`: `icon_back@2x.png` must be 88x88 pixels and `icon_back@3x.png` must be 132x132 pixels, with the image-set `Contents.json` mapping the `2x` and `3x` scales, the parent `Assets.xcassets/GeneralOB/Contents.json` enabling `provides-namespace`, and lookup name `GeneralOB/icon_back`. Implement the Figma bottom button's shared visual style directly in `GeneralOBVC.nextButton`, not in a page VC or page-specific override. BaseCell is not an OB page: do not create or modify a `GeneralOBPage` case, `pageData`, `page.vc`, `GeneralOBData`, `OB<Page>VC`, page-specific cell subclass, page asset namespace, or page status marker for it.
4. After the parent has completed and verified the optional BaseCell section, it dispatches exactly one subagent at a time for the next page not marked `done`. Do not dispatch another page agent until the active page agent's commit has been integrated. Each subagent owns exactly one page block and treats every Figma URL in that block as UI states of that one page.
5. Before dispatch, the parent marks only the active page `in_progress` in `OBFigma.md` with a lightweight status marker such as `<!-- ob-status: in_progress; attempts: 1 -->`. Only the parent edits queue status markers on the parent branch.
6. Each subagent reads every Figma URL in its assigned page block with the available Figma tools. It works in an isolated worktree, stages only its assigned page's implementation, assets, and required project metadata, then creates exactly one page-specific git commit after the page passes verification. Subagents must not directly modify shared `GeneralOB` files or `OBFigma.md` on the parent branch; the parent-owned BaseCell section is the explicit shared-foundation path for `GeneralOBBaseCell`, `GeneralOBVC.nextButton`, and `GeneralOB/icon_back`, and is completed before page subagents start.
7. If an assigned block has `### announcement`, treat every statement under it as a hard page-level implementation condition. A page's announcement takes precedence over every conflicting Workflow or Project Fit implementation rule for that page; all non-conflicting opening rules remain required. If the announcement mentions a reference image, reference document, attachment, filename, or relative path, search `OB-Task-Doc/` first and use that file as the authoritative reference before checking any other project location.
8. Each subagent inspects the iOS project before editing: `GeneralOB/Pages`, `GeneralOBPage`, `GeneralOBPage+Data.swift`, `GeneralOBPageData`, base classes, page routing, existing components, design tokens, assets, pods, and nearby screens.
9. Each subagent plans the mapping from its Figma layers to current project primitives, naming every reused component, base class, helper, asset, and library, plus how each announcement condition will be satisfied.
10. Add or update exactly one `GeneralOBPage` case for each new Figma page, then map that case to exactly one page implementation.
11. Name each new page file and class as `OB<Page>VC`, where `<Page>` is the PascalCase form of the `GeneralOBPage` case, such as `OBStartVC.swift` / `OBStartVC`.
12. Implement each ordinary Figma page in `GeneralOB/Pages` as a `GeneralOBVC` subclass or by extending the existing `GeneralOBVC` page flow, using the project's existing UI style, layout system, scaling helpers, font APIs, colors, lifecycle, and state patterns.
13. For option-style pages, subclass `GeneralOBCollectionVC` and source the option model from `GeneralOBPage.pageData.items` instead of rebuilding collection view plumbing from scratch, unless the page announcement explicitly forbids `UICollectionView`. When the page declaration contains `CollectionSection`, subclass `GeneralOBCollectionSectionVC` instead, even when the visible cell resembles `GeneralOBBaseCell`; implement the page-specific cell flow by overriding `registerCell()` and `cell(_ c: UICollectionView, path: IndexPath) -> GeneralOBBaseCell` using the current project's `OBSleepVC` pattern: call `super.registerCell()` before registering the page-specific cell, dequeue that cell only when `path.item > 0`, and otherwise return `super.cell(c, path: path)`. Also declare `override func sectionDetail(sec: Int) -> GeneralOBPageItem` to return the Figma-defined expanded information for that section; do not rely on the base placeholder or return an empty item. For other option-style pages, when a list cell is the inherited `icon` + `titleLab` + `checkIcon` layout and its title font and color match `GeneralOBBaseCell`, use `GeneralOBCollectionVC`'s default cell registration and dequeue flow; do not create a `GeneralOBBaseCell` subclass or override `registerCell` / `cell(_ c: UICollectionView, path: IndexPath)` just for that matching cell.
14. For option-list pages, set `page.multipleSelected = true` when the Figma interaction supports multiple selections; otherwise leave or set it to `false`.
15. For option-list pages, set `page.cellHeightIsConsistent = true` when every list cell has the same height in the Figma design; set `page.cellHeightIsConsistent = false` when cell heights can differ because of layout, expanded state, multiline content, or per-option design differences.
16. For list pages or any non-list page with tap-to-select behavior, add a matching property to `GeneralOBData` for persisted selection state: single-select index state uses `var page: Int?`, and multi-select index state uses `var page: [Int]?`, where `page` is the project-consistent property name for that `GeneralOBPage`.
17. For list pages, restore and save selection with `vc.makeSelectIndexes(...)` only in the external `GeneralOBPage` `page.vc` creation path; keep `makeSelectIndexes` out of `OB<Page>VC`, cells, and page-local helpers. Unless Figma or the page announcement explicitly specifies an initial selected option, do not provide a default selected index in `page.vc`; use only `GeneralOBData` for restored selection, and when `GeneralOBData` has no saved value call `vc.makeSelectIndexes([])`.
18. For non-list pages with tap-to-select behavior, restore selection from `GeneralOBData` during page setup, update the selected UI in the page's own state-rendering code, and save changes back to `GeneralOBData` in the tap handler; do not use `makeSelectIndexes` for non-list selection.
19. Initialize option items with both raw and localized titles, for example `GeneralOBPageItem(title: "abc", localizedTitle: #Localized("abc"), icon: "...")`.
20. When Figma shows an icon in a list item, export and use that exact Figma image asset for the item's `icon`, including its selected or unselected state where applicable. Do not substitute a Figma list icon with an SF Symbol, `UIImage(systemName:)`, `systemName:`, a drawn shape, or a runtime vector.
21. Never call `UICollectionView` reload methods such as `reloadData()`, `reloadItems(at:)`, or `reloadSections(_:)`; rely on `GeneralOBCollectionVC` data flow, diffable snapshots, selection APIs, or targeted state updates instead.
22. Do not call `makeSelectItems`, `makeSelectIndexes`, or any `makeSelect*` method inside the page implementation; those methods are reserved for the external code path that creates and initializes list page VCs.
23. For page-specific bottom continue button enabled, disabled, color, title color, or other state differences, override the inherited `nextBtnEnable` property and implement the state changes in its `didSet`; do not create a new helper method such as `updateNextButtonState`. This does not replace the BaseCell shared baseline: the bottom next button's common Figma visual style belongs directly in `GeneralOBVC.nextButton`.
24. When using `UIImageView` in page code, create it without assigning `contentMode`; do not set `.scaleAspectFit`, `.scaleAspectFill`, `.center`, or any other `contentMode` in the page implementation.
25. When a Figma page contains a circular progress view, use `GeneralOBCircleProgress` with `lineWidth = cx390(14)`, `trackColor = .init("#0F172A0D")`, and `gradientColors = [.init("#9E95FC"), .init("#5E7BFB")]`. Do not draw a new circular progress layer or substitute another progress control unless the page announcement conflicts with this rule.
26. When subclassing `GeneralOBBaseCell`, add new controls to `baseView`, prefer the inherited `titleLab`, `icon`, `checkIcon`, and `selectedBaseView`, preserve the base class's existing `checkIcon` image configuration without assigning new images, call `super.setupUI()` in overridden `setupUI`, and use SnapKit `snp.remakeConstraints` when adjusting inherited constraints.
27. If a list cell's selected UI differs from the base class behavior, override `isSelected` in the cell subclass and limit its `didSet` correction to foreground content such as `titleLab`, `icon`, and other cell text or image state. Do not assign `checkIcon.image` or `checkIcon.highlightedImage`, and do not change `baseView` or `selectedBaseView` backgrounds, borders, corner radius, shadows, gradients, or other selected-container visual effects in `isSelected`.
28. Every new or modified Figma page Swift file, including page-specific views and cells, must declare `import UIKit`, `import Components`, `import OOGFontKit`, `import OOGMacroKits`, and `import SnapKit` before its declarations, even when a module is not visibly referenced in that file. Localize every user-visible string with `#Localized("...")`.
29. When a page contains privacy policy and terms-of-use agreement text, implement it with `GeneralLinkTextView.createLinkView`, localized `Privacy Policy`, localized `Terms of Use`, localized `By continuing you agree to the %@ and %@`, and clickable `QACheck.PRIVACY_URL` / `QACheck.TERM_OF_USE_URL` links; do not use a plain `UILabel` or non-clickable attributed text for this agreement copy.
30. Add or update assets only when they are present in Figma or explicitly required; choose the resource format and scale supported by Figma and the project; put each page's exported image assets inside the matching `GeneralOBPage` folder under the `GeneralOB` asset namespace.
31. Keep title and subtitle layers above all other page content, including images, collection views, cards, decorations, gradients, and background art.
32. When the Figma page frame height is greater than `844`, put page content into a scrollable area while keeping the bottom continue button outside that scroll view so it stays fixed and visually floats above scrolling content.
33. Map Figma chrome visibility to `GeneralOBPage` metadata: no top-left back button means `page.canBack = false`, no top progress bar means `page.isHideProgress = true`, and no bottom continue button means `page.isHideContinueBtn = true`.
34. After each page implementation, do not run `xcodebuild` as page-completion validation. Verify project integration through source and project-file inspection, then verify layout responsiveness, safe areas, iPad or small-device variants, visual fidelity against the Figma screenshot, circular-progress control configuration when present, scroll behavior for frames taller than `844`, persisted selection restore/save behavior for both list and non-list selectable pages, Figma list-item icon asset use with no system-symbol fallback, cell subclass `isSelected.didSet` corrections when required, clickable privacy/terms agreement links when present, and all announcement conditions.
35. Each subagent returns its one page-specific commit hash, changed-file list, source/project-file/visual/interaction verification evidence, announcement compliance, and any shared-file integration conflicts. It does not update the parent branch's `OBFigma.md` marker or commit the parent branch.
36. After the active subagent returns, the parent integrates its successful page commit, resolves shared routing/data/assets conflicts, runs page source and project-file checks, updates the accepted page's `OBFigma.md` marker to `done`, then dispatches the next page agent. A failed page is retried before later pages are dispatched unless a genuine external blocker requires user input or an external state change.
37. After every page is integrated or explicitly blocked, run one workspace/project scheme `xcodebuild ... build` action for the complete queue. Do not run `xcodebuild` after individual pages. Then provide one consolidated summary of pages, agent outcomes, changed files, integration conflicts, page statuses, announcement conditions, fidelity compromises, and the final build result.

- A single `OBFigma.md` page block may contain multiple Figma links. All links in the same block belong to the same `GeneralOBPage` case and `OB<Page>VC` implementation, and represent different UI display states such as selected, disabled, expanded, empty, error, or alternate content states. Do not split them into separate pages, enum cases, files, or commits. This rule applies only to `## <id>` page blocks, not the `# BaseCell` section.

Treat all text under that heading until the next heading of the same or higher level as hard page-level implementation constraints for that page. Satisfy every announcement condition before marking the page `done`, and report how each condition was met.
- When reading each `OBFigma.md` page block, first apply every non-conflicting rule from the opening Workflow and these Project Fit Rules to that page. Do not treat queue mode as an exemption from those rules.
- If a page announcement mentions a reference image, reference document, attachment, filename, or relative path, resolve it from `OB-Task-Doc/` first. Use `rg --files OB-Task-Doc` or direct path checks before searching elsewhere, and report the resolved reference path.
- If a page announcement conflicts with any opening Workflow or Project Fit implementation rule, the announcement wins for that page. Apply all non-conflicting rules normally, and report the conflict plus the announcement-driven implementation choice instead of silently using the generic rule.
- For example, an announcement of `不使用UICollectionView` means the page must not use `UICollectionView`, `GeneralOBCollectionVC`, collection cells, or collection reload/update APIs, even if the Figma layout looks like a selectable option list. Implement it as an ordinary `GeneralOBVC` page or another existing non-collection project pattern while still preserving `GeneralOBPage` mapping and page data rules that remain applicable.
- Use a lightweight page status marker inside each `OBFigma.md` `## <id>` page block, for example `<!-- ob-status: todo -->`, `<!-- ob-status: in_progress; attempts: 1 -->`, `<!-- ob-status: failed; attempts: 1; reason: integration failed -->`, `<!-- ob-status: blocked; reason: <external dependency> -->`, or `<!-- ob-status: done; commit: <hash> -->`. Wait for its result and integrate its page commit before dispatching the next page agent. Each subagent creates exactly one page-specific git commit in its isolated worktree after success; do not have page subagents edit shared files or queue markers in the parent worktree.

Retry a failed page before later pages unless it has a genuine external blocker. After all pages are complete or blocked, run one workspace/project scheme `xcodebuild ... build` action and report its result in the unified final summary.

- If the current page announcement forbids `UICollectionView`, do not apply the option-style `GeneralOBCollectionVC` rule for that page. Use a non-collection implementation and explicitly verify that no `UICollectionView` symbols were introduced in the page-specific files.
- For option-list Figma pages, set `page.multipleSelected = true` when the page supports multi-select; otherwise ensure it remains `false`.
- For option-list Figma pages, set `page.cellHeightIsConsistent = true` when all collection cells have the same rendered height; set `page.cellHeightIsConsistent = false` when Figma shows variable heights or any selection/content state can change cell height.
- When Figma includes an icon in a list item, each matching `GeneralOBPageItem.icon` must reference the Figma-exported asset in the page namespace. Do not replace those icons with SF Symbols, `UIImage(systemName:)`, `systemName:`, generated vector drawing, or generic system artwork; export distinct selected and unselected Figma icon assets whenever the design shows distinct states.
- For list pages or any non-list page with tap-to-select behavior, add a matching persisted selection property to `GeneralOBData`. Use `var page: Int?` for single-select index state and `var page: [Int]?` for multi-select index state, where `page` is replaced with the project-approved property name for the `GeneralOBPage` case.
- For list pages, in the external `page.vc` creation path for the matching `GeneralOBPage`, restore and save selected index paths with `vc.makeSelectIndexes`. Single-select restores `[IndexPath(item: data, section: 0)]` from `GeneralOBData.shared.page` and saves `arr.first?.item`; multi-select restores `data.map { IndexPath(item: $0, section: 0) }` and saves the selected indexes array. If there is no saved value in `GeneralOBData`, call `vc.makeSelectIndexes([])`; do not default to selecting the first option or any other option unless Figma or an announcement explicitly requires that initial state.
- List-page selection restore/save belongs in the external `GeneralOBPage` `page.vc` or equivalent VC construction location. Do not put `makeSelectIndexes`, `makeSelectItems`, or any `makeSelect*` call inside `OB<Page>VC`, custom cells, or page-local selection/layout code.
- For non-list pages with tap-to-select behavior, do not use `makeSelectIndexes`. Restore the current value from `GeneralOBData` when building the page UI, render the selected/unselected state through a page-local state method or property, and update `GeneralOBData` whenever the user taps to change selection.
- Do not call `UICollectionView` reload APIs anywhere in Figma page implementations, including `reloadData()`, `reloadItems(at:)`, `reloadSections(_:)`, or wrapper helpers that call them. Use the existing `GeneralOBCollectionVC` diffable data source, `mainPage.pageData.items`, selection methods, and direct cell state updates instead.

For list pages, initial selection setup through `makeSelect*` belongs only to the external page creation or VC initialization location; for non-list tap-to-select pages, restore and save selection directly through `GeneralOBData`.
- Customize bottom continue button states by overriding `nextBtnEnable` and putting all enabled/disabled UI changes in its `didSet`, following `GeneralOBVC` and nearby pages such as `OBSexVC`. Do not add a new method or helper solely to refresh bottom button state.
- Do not assign `contentMode` on `UIImageView` instances in page implementations, page-local custom views, or cells; create image views and set their image/constraints without `.contentMode = ...`.

- Initialize every option `GeneralOBPageItem` with a raw `title` and localized `localizedTitle`, using the form `GeneralOBPageItem(title: "abc", localizedTitle: #Localized("abc"), icon: "...")`; do not set only `localizedTitle`, and do not place option display strings directly in cells.

- If the current list page's selected cell UI does not match the base class selected-state behavior, override `isSelected` in the custom cell subclass and apply the UI correction in `didSet` only to foreground content such as `titleLab` and `icon`. Do not assign `checkIcon.image` or `checkIcon.highlightedImage`; do not change `baseView`, `selectedBaseView`, their layers, borders, backgrounds, shadows, gradients, or other selected-container visuals; do not move selected UI correction into the page VC or external selection persistence code.

Preserve the base class container treatment and limit this override to title, icon, and other foreground-content updates; retain the inherited `checkIcon` image configuration.
- When Figma reports a component corner radius of `99` or `999`, treat it as a capsule shape and set the Swift corner radius to half of the component height, such as `height / 2` or `cx390(height) / 2`, instead of copying `99` or `999`.
- Store exported Figma page assets with the `GeneralOB/<page>/...` asset namespace pattern under `GeneralOB/Assets.xcassets/GeneralOB/<page>/`, where `<page>` matches the `GeneralOBPage` case or project-approved page asset name.
